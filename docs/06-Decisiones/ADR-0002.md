# ADR-0002: MapStruct para el mapeo DTO ↔ Entidad

- **Estado:** Aceptada
- **Fecha:** 2026-08-05
- **Decisión:** MapStruct 1.6.3 como generador de mappers tipo-safe en tiempo de compilación
- **Opciones descartadas:** Mappers manuales, ModelMapper (reflexión en runtime)

## Contexto

`TenantService.create` construye entidades desde `CreateTenantRequest` y arma `CreateTenantResponse` a mano (`buildResponse`). Conforme el sistema crezca (folder, document, version, permission, etc.), el mapeo manual se vuelve repetitivo y propenso a errores (campos que se omiten o se mapean mal).

## Opciones consideradas

### 1. MapStruct (seleccionada)

Genera la implementación de los mappers en tiempo de compilación.

**Ventajas:**
- Tipo-safe: un mapeo inválido falla en compilación, no en runtime
- Sin reflexión ni coste de performance en runtime
- Soporta Java records (constructor-based) y enums → String
- `componentModel = "spring"` genera beans inyectables
- Defines via `@Mapping`: ignores, defaults (`expression`), renombres (`id` → `memberId`)

**Desventajas:**
- Dependencia nueva + annotation processor en el build
- Curva de aprendizaje de `@Mapping`

### 2. Mappers manuales

**Ventajas:** sin dependencias.
**Desventajas:** boilerplate repetitivo, riesgo de errores silenciosos, difícil de mantener.

### 3. ModelMapper / Dozer

**Ventajas:** mapeo por convención sin definir mappers.
**Desventajas:** reflexión en runtime (más lento, sin tipo-safe en compilación), bugs difíciles de rastrear.

## Decisión

Se adopta **MapStruct 1.6.3** (estable, compatible con Java 21 y records). Un mapper por entidad dentro del sub-paquete `mapper/` de su feature (`tenant/mapper/`, `subscription/mapper/`, ...). Los mappers son interfaces `@Mapper(componentModel = "spring")`; el servicio inyecta el mapper de cada entidad y conserva solo la orquestación (derivación de `schema_name`, wiring de FKs).

## Consecuencias

- `pom.xml`: dependencia `org.mapstruct:mapstruct` + `mapstruct-processor` en `annotationProcessorPaths` (compile y testCompile).
- Los `*MapperImpl` se generan en `target/generated-sources` — no se versionan.
- Nuevos mappers por cada entidad que se agregue (folder, document, ...).
- Reglas de negocio (defaults, campos derivados) viven en el mapper (`@Mapping`/`expression`) o en el servicio; no duplicar lógica de BD.
