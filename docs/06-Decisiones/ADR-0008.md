# ADR-0008: Conexión Redis local y Spring Cache con serialización Jackson 3

- **Estado:** Aceptada
- **Fecha:** 2026-08-09
- **Decisión:** Agregar `spring-boot-starter-data-redis` (Lettuce) y `spring-boot-starter-cache`. Redis local en `localhost:6379` sin contraseña, configurable por variables de entorno (`REDIS_HOST`, `REDIS_PORT`). Habilitar `@EnableCaching` con un `RedisCacheManager` propio que serializa en JSON con `GenericJacksonJsonRedisSerializer` (Jackson 3) y typing restringido a `dev.achiri.multivault.*` y `java.util.*`. TTL base configurable (`cache.redis.time-to-live`, default 10m).
- **Opciones descartadas:** `org.testcontainers:redis` (no existe como artefacto en Maven Central), `GenericJackson2JsonRedisSerializer` (arrastra Jackson 2 al classpath), serialización JDK nativa de `RedisCacheManager` (binaria, no inspeccionable, más frágil), repositorios Spring Data Redis (no se usan; desactivados).

## Contexto

El proyecto va a necesitar caching (JWKS keys por tenant, rate limiting, configuraciones activas). Redis local está disponible como valkey 9.1.1 en `localhost:6379` sin `requirepass`. El proyecto ya definió en ADR-0007 que Jackson 3 (`tools.jackson.*`) es el único JSON library del classpath: agregar `GenericJackson2JsonRedisSerializer` rompería esa regla.

Spring Data Redis 4.x (incluido por Spring Boot 4.1) trae serializers Jackson 3 nativos (`GenericJacksonJsonRedisSerializer`, `JacksonJsonRedisSerializer`), por lo que no es necesario reintroducir Jackson 2.

## Opciones consideradas

### 1. `spring-boot-starter-data-redis` + `spring-boot-starter-cache` con `GenericJacksonJsonRedisSerializer` (seleccionada)

`RedisCacheManager` construido sobre `RedisConnectionFactory` con claves `RedisSerializer.string()` y valores JSON Jackson 3 con default typing validado por un `BasicPolymorphicTypeValidator` que solo permite subtipos de `dev.achiri.multivault.` y `java.util.`.

**Ventajas:**
- Sin Jackson 2 en el classpath (consistente con ADR-0007)
- Valores legibles en Redis (JSON) con hint de tipo `@class`
- Validación polimórfica restringe deserialización a paquetes propios (mitiga ataques de typing)
- `enableSpringCacheNullValueSupport()` permite cachear `null` (NullValue) sin fallos

**Desventajas:**
- Toda clase cacheada debe poder serializarse y debe vivir en `dev.achiri.multivault.*` o ser `java.util.*`
- Un `RedisCacheManager` propio anula la auto-configuración de Boot: las propiedades `spring.cache.redis.*` no aplican (el TTL se configura en Java)

### 2. Serialización JDK nativa (default de `RedisCacheManager`)

**Ventajas:** cero configuración adicional.

**Desventajas:** valores binarios no inspeccionables, incompatibilidad entre versiones de serialización, más superficie de ataque. Rechazada.

### 3. `GenericJackson2JsonRedisSerializer` (Jackson 2)

**Ventajas:** patrón conocido de la documentación.

**Desventajas:** reintroduce `jackson-databind` 2.x, que ADR-0007 eliminó explícitamente porque rompe la persistencia JSON de Hibernate (`AuditLog.metadata` es Jackson 3). Rechazada.

## Decisión

Se agregan ambas dependencias y se configura la conexión en `application.yaml` (`spring.data.redis.host`/`port` con defaults locales). Se crea `infrastructure/cache/RedisCacheConfig` con `@EnableCaching` y el bean `RedisCacheManager` descrito. Los repositorios Redis se desactivan (`spring.data.redis.repositories.enabled: false`) porque el proyecto usa repositorios JPA y no key-value stores.

En los tests de integración, Redis se levanta con Testcontainers (`GenericContainer` con imagen `redis:7-alpine` y `@ServiceConnection`, extendiendo ADR-0005). Se optó por `GenericContainer` en lugar del módulo `redis` de Testcontainers porque ese artefacto no existe en Maven Central (verificado en la versión 1.21.3 del BOM y en el directorio del repositorio central). El `RedisContainerConnectionDetailsFactory` de Boot 4.1 soporta cualquier `Container<?>` por nombre de imagen.

## Consecuencias

- La app requiere Redis en `REDIS_HOST:REDIS_PORT` (defaults `localhost:6379`) para arrancar con el perfil local
- Los tests de integración requieren Docker para levantar el contenedor de Redis junto al de PostgreSQL
- Cualquier caché (`@Cacheable`, etc.) debe usar entradas cuyo tipo raíz esté en `dev.achiri.multivault.*` o `java.util.*`; de lo contrario la deserialización falla por el type validator
- TTL por defecto 10 minutos para caches sin `cacheNames`/configuración propia; sobreescribible con `cache.redis.time-to-live` o configurando caches específicos en el `RedisCacheManager`
- No hay repositorios Spring Data Redis; el acceso directo a Redis (si se requiere para rate limiting/sesiones) se hará vía `StringRedisTemplate`/`RedisTemplate`
